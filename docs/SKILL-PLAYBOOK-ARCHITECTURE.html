Skill Playbook Architecture

Status: live as of 2026-07-31

Generator: scripts/build-playbooks.mjs

Supersedes: maps/SKILLS.html as the routing layer (that map rotted — see "Why the old map failed")

The problem this solves

Every Claude Code session injects name + description for every installed skill. Skill

bodies are already lazy — they load only on invocation — so the body size is free.

The description is the only thing you pay for at startup, on every turn, forever.

Two failures had compounded:

  • 78 skills all paying full description cost. ~7,758 tokens uncapped.
  • skillListingMaxDescChars: 160 was severing trigger vocabulary. 60 of 78

descriptions exceeded the cap. These descriptions are written "what it does" first,

"when to fire" second — so the cap kept the what and cut the when.

Measured damage from (2):

being unfireable, not unwanted.

The architecture

Tier 1 — visible, rich, uncapped descriptions. ~13 entries.

  • 6 playbook routers (pb-research, pb-orchestration, pb-codenav,

pb-verification, pb-frontend, pb-system). Each description carries the cluster's

"use when", its trigger vocabulary, and the list of skills it routes to.

  • 7 auto-firing reflexes (lesson, ponytail, reflect, classify-by-reading,

prove-before-claim, preflight-lessons, fan-out). These must fire unprompted, so

they keep their complete descriptions including all trigger phrases. Never demote these.

Tier 2 — bare name in the listing. ~45 skills with description: "".

Still fully invocable by name. The harness renders an empty-description skill as a bare

name (~15–20 chars) instead of ~400. Verified empirically 2026-07-31: a probe skill with

description: "" loaded its body normally on invocation and appeared in the listing as a

bare name.

The flow: agent hits a task → a tier-1 description matches → invokes the playbook →

the body loads (free until this moment) carrying the cluster table and disambiguation →

the body names the tier-2 skill → agent invokes that → its body loads. Three hops, each

paid only when relevant.

Why the old map failed

maps/SKILLS.html was the same idea, hand-maintained, and it rotted:

  • It listed skills that no longer exist on disk: dispatch, daytona, impeccable,

dogfood, ai-slop-cleaner, capability-router, siso-fleet-peer, convex-* (×6).

  • It listed as live many skills now marked status: retired: websearch, xsearch,

gitsearch, brain, os-database, checkmark.

  • Nothing loaded it. It was not injected and not referenced from the catalog, so no

agent ever routed through it and nothing surfaced the drift.

The fix is structural, not editorial: the playbooks are generated from the filesystem

on every run. A cluster member that no longer exists, or that has been retired, is dropped

at build time with a warning. Drift is impossible because nothing is hand-maintained.

Do not hand-edit pb-*/SKILL.md. Edit the CLUSTERS table in the generator and re-run.

Retired skills

27 of 79 skills on disk carry status: retired in their own frontmatter, and **all 27 have

zero recorded invocations** — a perfect correlation. They are excluded from all clusters.

They were not deleted: only 4 carried a supersession note, so the rest were retired

silently and the files are kept for archaeology.

Notable: all 7 firecrawl-* micro-skills are retired (the parent firecrawl documents the

full ladder); skill is retired because its scope is the banned oh-my-claudecode; os-database

is superseded by /task.

Known defects in live skills (flagged, not fixed)

  • codex-companion hardcodes gpt-5.5 at lines 32, 41, 67 — including the launch

command herdr pane run "$COMP" "codex -m gpt-5.5 ...". model-routing retired GPT-5.5

on 2026-07-11 in favour of gpt-5.6-sol. This skill will misroute. It also references

codex-fast, which orchestration-playbook marks RETIRED.

  • firecrawl backend is missing — the binary is not on PATH and no API key is set,

as of 2026-07-31. The skill has 10 invocations against a tool that may not run.

  • model-routing references GPT-5.5 in its own description.

Operating rules

  • Never demote a reflex. If a skill must fire without being asked for, it stays tier 1

with its full trigger vocabulary. Demoting it silences it.

  • skillListingMaxDescChars must be ≥ 400, or the tier-1 descriptions get severed and

the whole design inverts back into the original problem.

  • Re-run the generator after adding, retiring, or renaming any skill.

node scripts/build-playbooks.mjs (dry run) → --apply.

  • A playbook body is a router, not a runbook. It says which skill and why that one —

it never inlines the skill's instructions, or the laziness is lost.

  • Measure firing, not just cost. skill-events-hook.mjs (PostToolUse) and

skill-events-ingest.py (SessionEnd) log invocations. The success metric is whether

tier-2 skills get reached through playbooks, not whether the catalog got smaller.

Session 2026-07-31 — measured findings that drove the tooling

The headline: a session's cost is turns × accumulated context, not the size of what each turn adds. Session bf3518f3 billed 129,714,069 effective input tokens across 431 turns while creating only 169,070 tokens of new content — a 767× carry ratio. Context climbed 89,890 → 453,323. Median turn-to-turn growth: 380 tokens.

Content attribution (bf3518f3, one-time cost of everything ever added): tool_results 37.8%, tool_call_args 26.2%, assistant_prose 23.0%, user_text 13.0%. All of it totals 169k — roughly 0.1% of the bill. No category is the problem; the turn count is.

The counter-pattern that makes compression a trap. Stripping input drives the model to emit ~50% more output to compensate, and output bills ~5× input (rtk issue #582; squeez ships an explicit guard). Cache-aware weights — input ×1.0, cache-write ×1.25, cache-read ×0.1, output ×5 — are mandatory when measuring, or the provider's cache discount gets miscredited to your own change. Measured cache hit rate here was 98.2%.

What was built from this

  • scripts/ctx-attribute.mjs — read-only per-session attribution over Claude Code JSONL. Separates one-time content cost from re-billed carry. No proxy, no hook, nothing in the request path.
  • ~/.claude/hooks/context-depth-guard.mjs — PreToolUse advisory at 150k / 250k / 350k context. Non-blocking, once per band per session, fail-open. Verified firing on a live 346k session.
  • ~/.claude/hooks/postcompact-reinject.mjs — SessionStart(source=compact) hook that restores the PreCompact checkpoint. Closes a real gap: the checkpoint was being written and never read back. Capped at 1,500 chars because anything re-injected is re-billed every subsequent turn.
  • ~/.claude/hooks/serena-nudge.mjs — urges Serena over grep for code search only; silent on logs, JSONL, pipes, config. 13/13 unit cases plus a live end-to-end probe.
