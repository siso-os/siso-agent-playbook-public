2. rtk-ai/rtk

What it does
Filters and compresses command output before it reaches the LLM context — single Rust binary, 100+ commands.
Mechanism
Rust CLI binary that registers as a Claude Code / Codex / Cursor / Gemini / Cline / Pi / Kilocode / Hermes / Droid hook. The hook rewrites Bash commands (git status → rtk git status) before execution. Built-in tools like Read/Grep/Glob are NOT auto-rewritten — users must call rtk read/rtk grep/rtk find directly.
Technique
Per-command smart filtering (noise removal), grouping (files by directory, errors by type), truncation, deduplication. Examples: ls → tree with counts, git log → hash+author+subject only, pytest → failures only with trimmed traceback.
Claimed savings
"up to 90% of the bash output." RTK explicitly notes: bash output is one contributor to input tokens; reduction dilutes at every step. Percentages are bash-output-only, not whole-bill. Token estimates use bytes / 4.

TECHNIQUES WORTH STEALING

Distinct mechanisms seen across these 8 repos. Grouped by where in the pipeline they act.

A. Hook-layer command/output filtering (rtk, squeez, headroom, openwolf, lean-ctx)

  • Per-command format rewrite (rtk): replace git status with rtk git status; let a domain-aware binary render compact output. Limited to Bash tool (Claude Code's Read/Grep/Glob bypass the hook).
  • Log-template compaction (squeez): collapse near-identical log lines differing only by timestamps/IDs/values into one "[×N] <template>" line.
  • Exact-hash + fuzzy trigram-shingle dedup (squeez): cross-call dedup within a 16-call window, Jaccard ≥0.85; survives whitespace/timestamp jitter that defeats exact-hash.
  • Relevance-aware truncation (squeez): keep highest-relevance lines (error/signal words + terms from the command itself) instead of blind head/tail.
  • Identifier factsheet (squeez): carry exact git SHAs, UUIDs, ticket codes through every summary so lossy summarization never silently loses a hash.
  • Net-win gate (squeez): refuse to apply compression when savings < ~24 tokens — header cost makes it a net loss. Don't compress >0% cases by force.
  • Adaptive intensity (squeez): Full mode (<80% budget) → Ultra mode (≥80%) — calibrate compression aggressiveness to session pressure rather than always-on Ultra.

B. Reversible compression (headroom, lean-ctx, squeez)

  • Content-addressed store (CCR / similar): original bytes stashed in a CAS; compressed payload carries a handle; the LLM pulls the original back via a retrieve tool. Lets aggressive compression stay safe.
  • Trade-off: every repo uses a different storage shape (headroom local CAS, lean-ctx content-addressed with deterministic handles + 5 recovery paths, squeez content-addressed blobs with TTL pruning). The pattern is consistent — the implementation isn't.

C. Retrieval instead of reading (jcodemunch-mcp, openwolf, lean-ctx)

  • Tree-sitter AST indexing (jcodemunch-mcp): index once, retrieve exact symbols with byte-level offsets. Tools like find_references, get_blast_radius, find_importers, find_dead_code replace full file reads.
  • Symbol-level hints (openwolf): for files >500 tokens, index top-level symbols with line ranges; agent fetches one function via offset/limit instead of the whole file.
  • 10 read modes (lean-ctx): full / map / signatures / diff / lines:N-M / density:X — different fidelity per intent. Cached re-reads ~13 tokens.

D. Session / cross-chunk memory (lean-ctx, openwolf, squeez, headroom)

  • PreCompact snapshot + PostCompact re-injection (openwolf, squeez, headroom): snapshot state before compaction, re-inject as additionalContext afterward. Concrete state (files modified, error snippets, retrievable blob ids) survives the wipe.
  • Temporal validity windows (lean-ctx knowledge graph): facts carry valid_from/valid_to so they expire or update on a schedule.
  • Cross-agent shared brain (headroom wrap, openwolf .wolf/): one store shared across Claude/Codex/Gemini/Grok with auto-dedup.

E. Output-token reduction (headroom, squeez, rtk warning)

  • Verbosity steering (headroom): append a short "be terse, don't restate context" note at the end of the system prompt — keeps prompt cache hit intact.
  • Effort routing (headroom): when a turn is just the model resuming after a tool result (file read, passing test), dial thinking.budget_tokens/reasoning_effort down. New questions and errors keep full effort. Clamp-only, never zero.
  • Caveman persona (squeez): inject ultra-terse prompt at session start. persona = off | lite | full | ultra.
  • Counter-pattern warning (rtk issue #582 referenced in squeez README): aggressive command rewrite can INCREASE total cost by 18% because the model emits +50% more output tokens to compensate for stripped context. sques ships a guard against this regime. Don't strip input without watching the output.

F. Measurement & accounting (headroom, lean-ctx, squeez, codeburn, claude-devtools)

  • Cache-aware effective cost (squeez): list-price ratios (input ×1.0, cache write ×1.25, cache read ×0.1, output ×5) applied identically to both sides; never miscount the provider's caching discount as compression savings.
  • Real BPE verification (squeez): re-tokenize every fixture with cl100k_base; reported 0.5pt divergence from chars/4 estimate (83.5% real vs 83.0% chars/4) — proves the char estimate isn't a token-model artifact.
  • Tamper-evident savings ledger (lean-ctx ctx_proof/ctx_verify, 4-layer verification + ed25519-signed time-machine snapshots).
  • Per-turn 7-category attribution (claude-devtools): CLAUDE.md (global/project/dir) / skills / @-mentioned files / tool I/O / thinking / team overhead / user text — tell the user what's consuming context.
  • Realized vs estimated (codeburn codeburn act report): once an applied fix is ≥3 days old, compare estimated savings vs actual sessions. Closes the estimate↔reality loop.

G. Discovery / guard / budget (codeburn, headroom)

  • Waste-pattern scanner (codeburn codeburn optimize): re-read files, low Read:Edit ratio, uncapped BASH_MAX_OUTPUT_LENGTH, unused MCP servers, ghost skills, bloated CLAUDE.md, cache-creation overhead. Each finding has a ready-to-paste fix (CLAUDE.md line / env var / archive cmd).
  • Soft / hard / checkpoint caps (codeburn codeburn guard install): warn past $5, stop past $15, nudge past $3 if no edits/commits. Hooks fail open — broken guard never blocks a session.
  • CacheAligner warning (headroom): detects volatile content that would bust provider KV cache prefixes; warns but never rewrites the prompt.

H. Cross-tool surface (lean-ctx addon gateway, headroom wrap)

  • Addon gateway (lean-ctx): wraps any MCP server in a tiny lean-ctx-addon.toml manifest; one command wires it into the gateway; addon output is scrubbed for secrets and tagged untrusted before reaching the model.
  • headroom wrap + unwrap (headroom): one command installs proxy + Serena + agent config for 13+ tools; reverses cleanly. headroom wrap hot-syncs runtime env to the running proxy (no restart, no dropped requests, no lost caches).

Failure modes & caveats across the cohort

  • Counts vs cost dilution: rtk is explicit — "60-90% on bash output" is NOT "60-90% on your bill." Bash output is one input-token contributor; output tokens dilute the win. Headroom splits 20% on coding agents vs 60-95% on JSON for the same reason.
  • Tokenizers are not equal: squeez verified 83.5% with real BPE (cl100k_base) vs 83.0% with chars/4. Most projects report chars/4 only — fine for comparison, not for forecasting dollars.
  • Output can inflate when input is stripped: rtk issue #582 documented a regression where aggressive rewrite INCREASED total cost by 18% (model emits +50% output to compensate). Any input compressor without output accounting is risky.
  • Cache-busting is the silent killer: provider prefix-caches can lose 100% hit rate when a single volatile line (timestamp, counter, request id) lands in a stable prefix. CacheAligner (headroom) is the only project that surfaces this directly.
  • Hook surface gaps: Codex CLI has apply_patch hooks but no read_file/grep hook surface (openai/codex#18491); Gemini CLI's BeforeTool schema is pending docs (google-gemini/gemini-cli#25629). Squeez falls back to soft hints in AGENTS.md / GEMINI.md; OpenWolf uses protocol blocks.
  • No hook covers Agent/Task return value: PostToolUse updatedToolOutput (Claude Code v2.1.119+) covers built-in Read/Grep/Glob/Monitor but NOT the Agent/Task result. All projects surface this limit.
  • Verification difficulty: most "X% saved" claims are self-reported, on the maintainer's fixtures, with their own tokenizer. Realized-vs-estimated loops (codeburn act report, squeez cache-aware accounting) are rare and worth more than headline percentages.
