Cost Per Outcome: What We Know

The telemetry is a spend map, not yet an ROI table. Its headline reports only two completed tasks over seven days and an 8.7% task-ID/token join rate. Therefore lane-level “cost per delivered task” cannot be assigned honestly.

Decision interpretation

  • Opus is the first optimization target: even a small de-escalation rate moves more spend than perfecting Haiku.
  • M3’s cheap tokens are not free: verbose outputs, retries, and verifier time belong in the outcome denominator.
  • Codex is under-measured: no lane total means no fleet-economic comparison; add run-ledger tokens/cost/outcome before declaring it cheapest.
  • Task joins are the blocker: raise 8.7% attribution before using cost-per-outcome as a routing controller.
Provisional economic order for bounded, verifiable tasks: M3 first; Haiku when latency has value; Codex when its higher success rate prevents expensive retries; Opus only when judgment difficulty justifies it; Fable only where upstream decision quality changes many downstream outcomes. This is a C inference, not a measured SISO ranking.

Refined Escalation Ladder

The current “cheapest first, fail twice” ladder is too blunt. Escalation should begin with task classification, then respond to evidence. Two cheap failures can cost more than one correct expert pass; conversely, prestige routing creates the Opus burn visible in telemetry.

Classify the dominant difficulty. Bulk/latency → M3 or Haiku. Terminal iteration → Codex. Repo ambiguity → Opus. Irreversible planning/synthesis → Fable. Browse at scale → M3; GUI judgment → Opus.
Choose the cheapest model with benchmark fit—not merely cheapest token. Include likely attempts, verification cost, latency, and downstream reader burden.
Install a hard verifier before dispatch. Tests/compile/schema for code and extraction; source citations for research; explicit invariants for architecture. No verifier means route one tier higher or add a human gate.
Escalate on one diagnostic signal. Immediate escalation for misunderstood invariants, cross-module ambiguity, irreversibility, or repeated hallucinated state. Permit a second attempt only for mechanical/test-local failures with a new clue.
Escalate sideways by failure type. M3 mechanical failure → Codex. M3 semantic/repo failure → Opus. Opus plan uncertainty → Fable. Fable/Opus blind-spot risk → Sol cross-vendor review.
Use PAIR only at leverage points. Fable produces the plan or synthesis; Sol attacks it. For repo-critical patches, Opus authors/diagnoses and Codex reproduces/tests. Do not pair every task.
Reset context before raising model tier. Fresh session + compact external state can outperform escalation caused by a degraded, reused session—especially on M3 and long-running coordinators.
Record actual model, attempts, verifier result, and delivered artifact. De-escalate proven task classes after repeated passes; promote only from measured failure patterns.

Explicit Disagreements With Current model-routing

1
Opus 61.4 is resolved, not “effort-config dependent.” It is a v4.0 score. The comparable v4.1 score is 56. Remove the unresolved note and label index versions.
2
Haiku 4.5 should not be defined as an M3 alias. That is a local routing implementation fact, not a capability fact. Preserve a direct-Haiku lane for low-latency bounded work and log the served model.
3
“Start at the cheapest capable tier; fail twice” is not universally economical. Judgment-shaped repo bugs and irreversible architecture should route directly to Opus/Fable; one diagnostic failure is enough when invariants are misunderstood.
4
“Fable and Sol are peers” overgeneralizes a one-point composite gap. They are complementary: Fable leads planning/synthesis; Sol leads terminal execution and cross-vendor criticism. Composite adjacency does not imply interchangeable task performance.
5
M3 browse strength and research synthesis must be separated. BrowseComp/MCP Atlas support acquisition and navigation. Final contested synthesis still belongs to Fable/Opus, with Sol as verifier.
6
“M3 outbenches Sonnet” is too broad to justify a universal ban. A composite index and price do not prove dominance on every task class. A ban may remain a fleet policy, but it is not benchmark-settled by the cited evidence.
7
Cost claims need outcome attribution. The current skill points to telemetry as posterior truth, but the supplied telemetry joins only 8.7% of tokens to task IDs. Treat economics as provisional until that instrumentation improves.
