SISO L0 Efficiency Engine

Nightly, read-only rollup that joins router spend, Claude session context, direct-MiniMax spend, and completed task ledgers into one static report.

Run

/usr/bin/python3 /Users/shaansisodia/SISO_Workspace/.agents/telemetry/bin/efficiency-rollup.py

Use --reset only when intentionally rebuilding JSONL state. Normal runs compare size + mtime and parse only appended bytes. State is written to state/scan-state.json.

Accounting

  • Local days are UTC+7.
  • Session tokens are input + output + cache-read input.
  • Bifrost uses total_tokens; its prompt_tokens already includes cached reads, so cached reads must not be added twice.
  • Primary estate burn is Bifrost plus direct MiniMax, because direct MiniMax bypasses the router.
  • Claude session totals are not added to primary burn; doing so would double-count router-backed traffic.
  • First non-harness user prompts supply TASK IDs. Multiple IDs split a session's tokens evenly so attribution remains conservative.
  • Task completion timestamps prefer explicit fields, then done/completed/closed execution-log events, then documented fallbacks.

Outputs

  • efficiency.json: machine-readable facts and quality metadata.
  • EFFICIENCY.html: no-JavaScript dark report.
  • state/scan-state.json: per-file offset, size, mtime, running totals, prompts, and turns.
  • launchd/com.siso.efficiency-rollup.plist: written but intentionally not installed.

Extend

Add a source scanner that returns normalized day/lane/token records plus freshness metadata. Keep live sources read-only, make the source's token definition explicit, and decide whether it is primary burn or attribution-only before merging it.

Known denominator limitation: completed task files measure ledger closure, not quality, human-review minutes, rework, or latency. The JSON schema leaves room for those outcome fields when dispatch contracts begin emitting them.
